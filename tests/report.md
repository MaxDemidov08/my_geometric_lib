# Тестирование

## 1. Цели и задачи тестирования

Целью тестирования является проверка корректности работы программных модулей, реализующих вычисление площади и периметра геометрических фигур.

Основные задачи тестирования:

1. Проверка правильности вычислений при положительных входных значениях.
2. Проверка поведения функций при передаче нулевых значений.
3. Проверка обработки отрицательных чисел.
4. Проверка работы функций с числовыми значениями, переданными в виде строк.
5. Проверка возникновения исключений `ValueError` при передаче недопустимых значений.
6. Выявление ошибок и несоответствий в работе программных модулей.

## 2. Описание тестируемого продукта

Тестируемый программный продукт представляет собой библиотеку геометрических вычислений, разработанную на языке Python в ходе предыдущих лабораторных работ.

Библиотека состоит из четырёх модулей:

- `circle.py` — вычисление площади и периметра круга.
- `square.py` — вычисление площади и периметра квадрата.
- `rectangle.py` — вычисление площади и периметра прямоугольника.
- `triangle.py` — вычисление площади и периметра треугольника.

Каждый модуль содержит две функции:

- `area()` — вычисление площади геометрической фигуры.
- `perimeter()` — вычисление периметра геометрической фигуры.

Функции принимают параметры, соответствующие геометрическим характеристикам фигур, и возвращают результаты вычислений.

В процессе тестирования проверяется корректность обработки различных типов входных данных, включая положительные, нулевые и отрицательные значения, а также числовые строки.

## 3. Область тестирования

Область тестирования включает проверку функций вычисления площади и периметра всех четырёх геометрических фигур.

Тестированию подлежат следующие функции:

| Модуль | Функция | Назначение |
|---|---|---|
| `circle.py` | `area(r)` | Вычисление площади круга |
| `circle.py` | `perimeter(r)` | Вычисление длины окружности |
| `square.py` | `area(a)` | Вычисление площади квадрата |
| `square.py` | `perimeter(a)` | Вычисление периметра квадрата |
| `rectangle.py` | `area(a, b)` | Вычисление площади прямоугольника |
| `rectangle.py` | `perimeter(a, b)` | Вычисление периметра прямоугольника |
| `triangle.py` | `area(a, h)` | Вычисление площади треугольника |
| `triangle.py` | `perimeter(a, b, c)` | Вычисление периметра треугольника |

Для каждой функции разработано по шесть тестов, проверяющих:

1. Корректность вычислений при положительных входных значениях.
2. Корректность вычислений при передаче нулевых значений.
3. Обработку первого отрицательного значения.
4. Обработку второго отрицательного значения.
5. Корректность работы с положительными числами, переданными в виде строк.
6. Обработку отрицательных чисел, переданных в виде строк.

Таким образом, общее количество разработанных тестов составляет **48**.

## 4. Стратегия тестирования

Для проверки корректности работы библиотеки применяется модульное тестирование (Unit Testing).

Тестирование осуществляется с использованием стандартной библиотеки Python `unittest`.

Выбран метод функционального тестирования по принципу «чёрного ящика», при котором проверяется соответствие результатов выполнения функций ожидаемым значениям без анализа их внутренней реализации.

Для проведения тестирования создан отдельный файл `test_geometry_lib.py`, содержащий четыре тестовых класса:

- `CircleTestCase` — тестирование функций круга.
- `SquareTestCase` — тестирование функций квадрата.
- `RectangleTestCase` — тестирование функций прямоугольника.
- `TriangleTestCase` — тестирование функций треугольника.

Каждый класс наследуется от `unittest.TestCase` и содержит 12 тестовых методов.

Для проверки результатов используется метод:

```python
self.assertEqual(actual, expected)
```

Метод проверяет соответствие фактического результата ожидаемому значению.

Для проверки обработки недопустимых значений используется:

```python
with self.assertRaises(ValueError):
    ...
```

Метод `assertRaises()` проверяет, что при выполнении функции возникает ожидаемое исключение `ValueError`.

Для проведения тестирования используются следующие категории входных данных:

**1. Положительные значения**

Позволяют проверить правильность математических вычислений при стандартных условиях использования программы.

**2. Нулевые значения**

Позволяют проверить поведение функций в граничных случаях, когда один или несколько входных параметров равны нулю.

**3. Отрицательные значения**

Позволяют проверить корректность обработки недопустимых геометрических параметров.

При передаче отрицательных чисел ожидается возникновение исключения `ValueError`.

**4. Положительные числа в виде строк**

Позволяют проверить возможность преобразования строковых значений в числовой тип.

Например:

```python
self.assertEqual(SquareArea("3"), 9)
```

**5. Отрицательные числа в виде строк**

Позволяют проверить корректность обработки отрицательных значений, переданных в строковом формате.

Например:

```python
with self.assertRaises(ValueError):
    SquareArea("-3")
```

Для запуска тестирования используется команда:

```bash
python -m unittest tests/test_geometry_lib.py
```

Исходный код тестируемых модулей в процессе выполнения лабораторной работы не изменяется.

## 5. Критерии приёмки

Основным критерием успешного прохождения тестирования является соответствие фактических результатов вычислений ожидаемым значениям и корректная обработка недопустимых входных данных.

Для каждого теста определены входные параметры и ожидаемый результат.

| № | Категория тестирования | Входные данные | Ожидаемый результат |
|---|---|---|---|
| 1 | Положительное число | `SquareArea(5)` | `25` |
| 2 | Нулевое значение | `SquareArea(0)` | `0` |
| 3 | Первое отрицательное число | `SquareArea(-5)` | `ValueError` |
| 4 | Второе отрицательное число | `SquareArea(-10)` | `ValueError` |
| 5 | Положительное число в строке | `SquareArea("3")` | `9` |
| 6 | Отрицательное число в строке | `SquareArea("-2")` | `ValueError` |

Аналогичные проверки выполняются для всех восьми функций библиотеки.

Тест считается успешно пройденным, если:

- Возвращаемое значение совпадает с ожидаемым.
- При передаче отрицательных значений возникает исключение `ValueError`.
- Числовые строки корректно преобразуются в числа.
- При передаче отрицательных чисел в строковом формате возникает исключение `ValueError`.

При обнаружении несоответствий тест считается проваленным.

Если во время выполнения теста возникает необработанное исключение, тест завершается с ошибкой.

Для полного успешного прохождения тестирования необходимо, чтобы все 48 тестов завершились без провалов и ошибок.

### Анализ результатов

В ходе тестирования выявлены два типа неуспешных результатов.

**1. Проваленные тесты (FAIL)**

Зафиксировано 22 проваленных теста.

Провал теста означает, что фактический результат выполнения функции не соответствует ожидаемому.

Например, если тест ожидает возникновения исключения `ValueError` при передаче отрицательного числа, но функция возвращает числовое значение, тест считается проваленным.

Пример:

```python
def test_area_negative_1(self):
    with self.assertRaises(ValueError):
        SquareArea(-5)
```

Если функция возвращает `25` вместо вызова исключения, тест завершается с результатом `FAIL`.

**2. Тесты, завершившиеся с ошибкой (ERROR)**

Зафиксировано 10 тестов, завершившихся с ошибками.

Ошибка возникает, когда во время выполнения теста появляется необработанное исключение.

Например, при передаче строковых значений функция может вызвать `TypeError`, если не предусмотрено преобразование строк в числа.

Пример:

```python
def test_area_string(self):
    self.assertEqual(RectangleArea("3", "4"), 12)
```

Если функция пытается напрямую перемножить две строки, возникает исключение:

```text
TypeError: can't multiply sequence by non-int of type 'str'
```

В результате тест завершается с ошибкой.

**3. Успешно пройденные тесты**

Из 48 тестов успешно завершились 16.

Это означает, что в данных случаях функции вернули ожидаемые значения либо корректно вызвали предусмотренные исключения.

Однако полученных результатов недостаточно для подтверждения полной корректности работы библиотеки.

### Возможные причины выявленных проблем

На основании результатов тестирования можно предположить следующие причины неуспешного выполнения тестов:

1. Отсутствие проверки входных данных на отрицательные значения.
2. Отсутствие вызова исключения `ValueError` при передаче недопустимых параметров.
3. Отсутствие преобразования числовых строк в числа.
4. Выполнение арифметических операций над несовместимыми типами данных.
5. Несоответствие поведения функций требованиям, установленным в тестах.

Для определения точных причин необходимо проанализировать сообщения об ошибках каждого неуспешного теста.
